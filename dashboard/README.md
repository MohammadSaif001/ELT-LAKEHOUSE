# Pipeline Monitoring Dashboard

The dashboard is a read-only FastAPI application for inspecting the local
ELT-Lakehouse run state. It reports execution status from the pipeline log,
local storage availability, defined data-quality test suites, Gold model
definitions, recent log events, and a machine-readable health endpoint.
The Gold Layer page summarizes the dbt dimensions and facts, their grains,
the star-schema relationships, and model runtimes. When available,
the dashboard reads model statuses and test results from
`dbt_gold/target/run_results.json`, and compares the saved report time with the
latest orchestration start.

It does not start pipeline jobs, schedule work, or modify pipeline data.

## Requirements

Install the project dependencies from the repository root:

```bash
uv sync
```

The dashboard's standalone dependency list is also available in
[`requirement.txt`](requirement.txt), but using `uv sync` is preferred because
it installs the complete project environment.

## Run locally

From the repository root:

```bash
uv run uvicorn dashboard.app:app --reload --host 127.0.0.1 --port 5000
```

Then open <http://127.0.0.1:5000>.

The equivalent module entry point is:

```bash
uv run python -m dashboard.app
```

The application reads the project root relative to `dashboard/app.py`, so it
should be run from a checkout containing `logs/`, `metadata/`, and `storage/`.
Missing or not-yet-created runtime data is shown as an explicit pending or
unknown status rather than being generated by the dashboard.

Dashboard service diagnostics are written to `logs/dashboard.log`. Pipeline
execution events remain in `logs/application.log`; the dashboard does not
write its own service messages to that file.

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Overview: KPIs, latest-run timeline, run and stage trends, log activity, health checks, dbt, storage |
| `/pipeline-run` | Per-stage and per-job status, stage timing, run history |
| `/data-quality` | dbt test results and test inventory |
| `/storage-health` | Bronze, Silver and Gold size, file counts, metadata state files |
| `/gold-layer` | Gold dbt model catalog, star schema, model runtimes |
| `/technical-details` | Filterable application log, config files, data sources |
| `/stage/{stage_key}` | Detail for a single pipeline stage |
| `/api/health` | JSON health response (503 when a check fails) |
| `/api/telemetry` | The chart data behind every graph, as JSON |

## Telemetry

Every graph is built from files the pipeline already writes. Nothing is
generated or estimated.

| Graph | Source |
| --- | --- |
| Latest run timeline, stage duration per run | Stage logger events in `logs/application.log`. Exact when the completion message contains `duration_s=...`, otherwise derived from event timestamps. |
| Run duration, outcomes, success rate | `elt_pipeline` start, success and failure messages. |
| Log activity, events by stage | Parsed pipeline lines from `logs/application.log`, grouped by level, time bucket and logger. |
| dbt tests and model runtime | `dbt_gold/target/run_results.json`. |
| Storage size | Size and file count of `storage/*`. |

Runs are separated by the `Starting ELT pipeline` message: everything up to the
next start belongs to that run. A run with no success or failure message is
shown as incomplete. If a source is missing, its graph says so instead of
drawing zeros.

Charts are plain SVG drawn by `static/js/charts.js`, so there are no new
Python or JavaScript dependencies and nothing is loaded from a CDN. The
dashboard follows the system light or dark setting. All colours are tokens at
the top of `static/css/report.css`.

The **Refresh** button reloads the page. **Auto-refresh** reloads every 30
seconds and remembers its setting in the browser.
